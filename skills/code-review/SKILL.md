# 代码审查流程

## 硬性检查（逐条过，不要跳）

1. **边界条件**：空输入、None、越界、除零、空列表
2. **异常处理**：有没有裸 `except:`？异常被静默吞掉了吗？抛出的异常有信息量吗？
3. **资源释放**：文件、连接、子进程有没有用 `with` / `finally`？
4. **可变默认参数**：`def f(x=[])` 是经典坑，会跨调用共享状态
5. **真值判断**：`if x == None` 应为 `if x is None`；`if not x` 会误伤 0 和空字符串
6. **路径处理**：用 `pathlib.Path` 还是字符串拼接？相对路径会受 cwd 影响

## 审查方法

1. **先完整读完文件再下结论**，不要看一段说一段（用 `read`，必要时用 `offset` 分段）
2. 引用具体位置，格式为 `相对路径:行号`，例如 `core/node.py:57`
3. 每个问题都要说清**为什么是问题**（会导致什么后果），并附一句修改方向

## 输出格式

```
## 严重问题（会导致 bug）
- `path/file.py:42` 问题描述 → 建议

## 建议改进（风格 / 可读性）
- ...

## 总体结论
一句话评价。
```

## 不要做的事

- 不要为了凑数而提无关紧要的格式问题
- 不要建议引入新依赖，除非现有依赖确实做不到
- 不要只指出问题而不给方向
